# 数据集构建

本目录记录中文学术文本 AIGC 检测数据集的构建方案。目标不是简单拼接两批“人类文本”和“AI 文本”，而是建立来源清楚、具有配对关系、能够验证润色与跨模型泛化问题的数据集。

当前第一阶段只研究**中文论文摘要**。正文段落和完整论文留到后续阶段，第一阶段实验结论也只解释为“摘要检测结果”。

详细执行方案见：[摘要数据方案](摘要数据方案.md)。

## 1. 数据单位

第一阶段以一篇论文的**摘要**为基本样本。摘要天然具有题目、关键词和学科标签，便于构造语义配对的纯生成和轻度润色版本，也省去 PDF 正文抽取与章节识别。

初期保留长度约 150—600 个中文字符的摘要。长度阈值在查看真实分布后再调整，不能为了满足阈值随意截断摘要。

## 2. 标签体系

每个人类原始段落分配一个唯一的 `group_id`，并围绕它构造多个配对版本。

| 标签 | 含义 | 构造方式 |
|---|---|---|
| `human` | 人类原文 | 从合法获得的中文论文中抽取，优先选择生成式 AI 普及前发表的论文 |
| `ai_full` | 纯 AI 生成 | 只提供题目、关键词、学科和段落功能，不提供人类原文 |
| `ai_polish_light` | 轻度 AI 润色 | 只修改语法、用词和流畅度，不增删观点，不改变结构 |

标签描述的是**文本形成过程**，不是根据检测器分数反推的标签。商业工具给出的“AI 率”不能作为真实标签。

## 3. 人类文本来源

候选来源按优先级排列如下：

1. [CSL 中文科学文献数据集](https://github.com/ydli-ai/CSL)：首选来源；
2. 作者明确授权使用的学术摘要；
3. 其他具有清晰开放许可的中文论文摘要语料；
4. 由受试者在受控条件下独立撰写的新摘要。

CSL 收录约 39.6 万篇 2010—2020 年中文核心期刊论文的题目、摘要、关键词和学科标签，项目仓库标注为 Apache-2.0 许可。正式使用时仍需保留数据来源、版本和许可说明。

2022 年以后发表的论文不能仅凭发表时间认定为纯人工文本。即使是早期论文，也可能经过翻译或自动写作工具处理，因此要记录来源和标签可信度。

不得将未公开投稿论文、含个人隐私的论文或受版权限制的全文直接提交到公共仓库。原始数据应存放在受控位置，仓库只保存处理脚本、元数据规范和允许公开的派生数据。

## 4. AI 文本生成

第一阶段至少选择 2—3 个中文能力较强、来源不同的模型。不同模型使用相同任务模板，并保存模型名称、版本、生成日期和参数。

### 4.1 纯生成

只提供题目或泛化主题、3—6 个关键词、学科、段落类型和目标长度。不能提供人类原文，否则模型可能只是在复述原文。

### 4.2 轻度润色

要求模型不增删事实、数据、观点和引用，不改变段落结构，只修改语法、搭配、冗余表达和流畅度。

所有提示词都必须带版本号并保存原文，不能在实验过程中调整提示词却不记录变更。

## 5. 数据清洗

1. 读取结构化的题目、摘要、关键词、学科和门类；
2. 统一 Unicode、空白字符和换行；
3. 过滤空摘要、明显乱码、模板残缺和重复摘要；
4. 标记包含公式、表格占位符或异常符号的样本；
5. 计算字符数，并查看各学科的长度分布；
6. 按学科与长度分层抽样；
7. 为人类摘要及其全部派生版本分配相同的 `group_id`。

不应过度清洗标点、句式和功能词，因为它们可能正是检测方法使用的特征。人类文本和 AI 文本必须经过相同的清洗流程。

## 6. 数据字段

| 字段 | 说明 |
|---|---|
| `sample_id` | 当前样本的唯一编号 |
| `group_id` | 人类原文及其派生版本共享的编号 |
| `text` | 清洗后的正文 |
| `label` | `human`、`ai_full`、`ai_polish_light` 等 |
| `discipline` | 学科类别 |
| `section_type` | 摘要、引言、方法、讨论等 |
| `source_year` | 人类原文发表或写作年份 |
| `source_id` | 原始论文或文档的内部编号 |
| `generator_model` | 生成模型名称 |
| `generator_version` | 模型版本 |
| `prompt_version` | 提示词版本 |
| `temperature` | 生成温度，未知时留空 |
| `source_text_provided` | 生成时是否提供人类原文 |
| `generation_date` | 生成日期 |
| `human_edit_level` | 生成后人工修改程度 |
| `char_count` | 中文字符数 |
| `split` | train、validation 或 test |

## 7. 数据划分与防止泄漏

所有具有相同 `group_id` 的样本必须进入同一个数据划分。同一篇论文的不同段落也应尽量放在同一个集合中。

严禁把全部段落随机打散后再划分训练集和测试集，否则模型可能通过作者习惯、论文主题或相似句子认出同源文本，得到虚高结果。

至少建立三种测试设置：

1. **同分布测试**：训练集和测试集包含相同生成模型，但论文来源完全分离；
2. **生成模型留一测试**：训练时完全去掉一个模型，测试时只检测该模型；
3. **学科留一测试**：训练时完全去掉一个学科，测试时只评估该学科。

后续可以增加时间留一、提示词留一和文本长度迁移测试。

## 8. 第一阶段规模

先构建小规模试运行集：

- `human`：100 篇摘要；
- `ai_full`：100 篇摘要；
- `ai_polish_light`：100 篇摘要；
- 生成模型：至少 2 个；
- 学科：至少 2 个；
- 每个人类摘要与两个 AI 版本共享同一个 `group_id`。

试运行通过后，再扩展到每类 300—1000 个段落。优先增加来源、模型和学科的多样性，而不是只用同一个模型批量生成相似文本。

## 9. 数据质量检查

- 纯生成文本是否意外复述了输入材料；
- 润色文本是否改变事实、数字或引用；
- 不同标签之间的长度分布是否严重失衡；
- 人类和 AI 数据是否经过相同清洗；
- 是否存在完全重复或高度相似样本；
- 不同数据划分中是否出现相同 `group_id` 或相同论文来源；
- 是否记录所有模型与提示词版本；
- 是否抽样进行人工复核并记录争议样本。

## 10. 目录规划

```text
数据集构建/
├── README.md
├── config/              # 模型与接口的非敏感配置
├── prompts/             # 带版本号的生成提示词
├── scripts/             # 抽样、生成、导入与合并脚本
├── source/              # 可重新下载的原始基准数据，本地保存
├── raw/                 # 原始数据，不提交敏感或受限文本
├── generated/           # 模型原始生成结果，本地保存
└── processed/           # 完成标签、清洗和划分的数据
```

第一步先完成 100 组人类段落及其配对版本。只有数据流程和标签定义稳定后，才扩大数据规模。
