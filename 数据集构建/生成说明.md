# 摘要生成说明

## 1. 准备配置

```bash
cp .env.example .env
```

仓库已经提供 `数据集构建/config/providers.json`，无需复制。

把中转站统一的 Base URL 和 API Key 写入 `.env`：

```text
RELAY_BASE_URL=https://中转站地址/v1
RELAY_API_KEY=你的密钥
```

`.env` 已被 Git 忽略。三个模型的名称和接口方式记录在 `数据集构建/config/providers.json` 中，不包含密钥，可以提交。

当前默认假设中转站提供 OpenAI 兼容的 `POST /chat/completions` 接口。如果中转站使用其他路径或模型名称，需要按其文档修改 `providers.json`。

## 2. 检查提示词展开

```bash
python3 数据集构建/scripts/generate_abstracts.py \
  --input 数据集构建/processed/csl_cs_20_human_abstracts.csv \
  --output 数据集构建/generated/dry-run.jsonl \
  --provider openai \
  --config 数据集构建/config/providers.json \
  --task all \
  --limit 1 \
  --dry-run
```

`dry-run` 不需要密钥，也不会调用 API。

## 3. 单篇接口测试

先让每个模型处理同一篇摘要：

```bash
python3 数据集构建/scripts/generate_abstracts.py \
  --input 数据集构建/processed/csl_cs_20_human_abstracts.csv \
  --output 数据集构建/generated/openai.jsonl \
  --provider openai --task all --limit 1
```

把 `openai` 分别替换为 `deepseek` 和 `anthropic`。人工检查6条生成文本通过后，再去掉 `--limit 1` 批量运行。

## 4. 断点续跑

脚本以 JSONL 追加写入。再次运行时，状态为 `success` 的 `sample_id` 会自动跳过；失败记录会保留，并在下一次运行时重新尝试。

输出目录默认被 `.gitignore` 忽略，以免误提交原始 API 响应或实验数据。确认数据许可和脱敏状态后，再决定发布哪些派生文件。
